---
title: 왜 spawn-ui인가
description: spawn의 CSS를 세어 보고 알게 된 것
---

spawn은 화면을 하나씩 만들면서 CSS도 화면마다 따로 그렸어요. 2026년 11월 23일, spawn의 스타일시트 10개(2,730줄)를 전부 세어 봤어요.

## 숫자로 본 spawn (2026-11-23)

| | 값 |
|---|---|
| 눈에 보이는 모양의 종류 | **73가지** |
| 그 모양들을 따로 정의한 횟수 | **257번** |
| 그 정의들의 CSS 줄 수 | **1,862줄** |
| 어디서도 쓰이지 않는 CSS | 35규칙, 66줄 |

같은 모양이 평균 3.5번씩 따로 그려져 있었어요.

## 가장 많이 겹친 것

| 모양 | 따로 정의된 횟수 | 비고 |
|---|---|---|
| 버튼 | 38번, 208줄 | 높이 24 · 28 · 약 30px |
| 아이콘 버튼 | 23번 | 크기 12가지(20px ~ 56×44) |
| 상태 점 | 12번 | 모두 6px 원 |
| 태그 | 12번 | |
| 알림 문구 | 11번 | |
| 칸 나누기 버튼 | 10번 | |

포커스 링은 전체에 한 번 정해 두고도 11번 더 똑같이 다시 써 있었어요. 반대로 같은 이름이 화면마다 조금씩 다른 경우도 있었어요. 고른 항목의 바탕은 줄에서 4%, 레일에서 5%, 칸 나누기에서 6% 흰색이에요.

## 그래서

- **하나로 합쳐요.** 닮은 것은 한 컴포넌트의 변형으로 묶어요. 예를 들어 버튼 38벌은 `Button` 하나가 돼요.
- **화면은 그대로 둬요.** spawn에 있던 크기와 색을 그대로 변형으로 남겨서, 옮겨도 픽셀이 바뀌지 않게 해요. 크기를 통일하는 건 따로 정해서 해요.
- **규칙은 테스트로 지켜요.** spawn이 지켜 온 규칙(노랑, 회색, 포커스 링, 굵기, 모서리, 움직임)을 그대로 테스트로 걸어요. [디자인 원칙](../principles/)에 정리해 뒀어요.
- **쓰지 않는 건 버려요.** 아무 데서도 쓰지 않는 66줄은 옮기지 않고 spawn에서 지워요.

조사 원본은 저장소의 [docs/inventory.md](https://github.com/DueStar/spawn-ui/blob/main/docs/inventory.md)에 있어요.
